# FR-09 — สรุปบันทึกยืนยันรายสัปดาห์

สถานะ: Draft สำหรับตรวจ ยังไม่รวม main ยังไม่รับรอง Firebase/Gemini หรือมือถือจริง เจ้าของงานยังต้องอ่านและอธิบายโค้ดด้วยตนเอง

อ้างอิง [SRS §3.3](../../docs/01-requirements/spec.md), [Architecture](../../docs/02-design/architecture.md) และ [หน้าจอ C-10](../../docs/02-design/design-system.md) ส่วนเพิ่มอยู่ตามโครงสร้างเดิม: โค้ดใน `public/`, เทสต์ใน `tests/` และเอกสารประจำฟีเจอร์ในโฟลเดอร์นี้

## ขอบเขต

- สรุป 7 วันปฏิทินที่จบแล้วก่อนวันนี้ ไม่รวมวันนี้ ใช้เขตเวลาของเครื่องผู้ดูแล
- อ่านเฉพาะ Dose ยืนยันที่มีจริง ไม่สร้างประวัติจากตารางยาปัจจุบัน วันไม่มีรายการคือไม่มีบันทึก ไม่ใช่หลักฐานพฤติกรรมการกินยา และไม่คำนวณอัตรากินยาครบ
- หากมี valid confirmation อย่างน้อย 1 รายการ จะสรุปเฉพาะข้อมูลที่มี หากไม่มีรายการจะไม่เรียก AI
- AI เลือก 1–3 ประเด็นจากประโยคที่แอปคำนวณจากข้อเท็จจริง ไม่แสดงข้อความอิสระจากโมเดล แนวทางนี้เป็นข้อเสนอให้ทีมตรวจเทียบกับ story เดิมที่ใช้คำว่า AI-written summary
- คำขอจริงมี `days` (ลำดับวัน เวลา สถานะ) และ `candidates` (ประโยค/สถิติจากข้อมูลนั้น) ผู้ดูแลดูทั้งหมดก่อนยินยอม ไม่มีวันจริง ID ชื่อ HN รายละเอียดยา หรือคำแนะนำยา
- ข้อมูลจริงอ่านจาก server เฉพาะคู่ที่ผู้ดูแลได้รับความยินยอม ตรวจสิทธิ์ซ้ำและล้างหน้าจอเมื่อยกเลิกจับคู่ ไม่มีคำสั่งเขียนหรือลบข้อมูล
- ใช้ snapshot เมื่อโหลด มีปุ่มโหลดใหม่ ไม่ใช่ข้อมูลที่อัปเดตสด และยังไม่รองรับการเปลี่ยนเขตเวลาอย่างสมบูรณ์

## ทดลอง

เปิดโฟลเดอร์ `public/` ผ่าน static server แล้วเข้า `weekly-summary.html` หน้าใหม่เริ่มด้วย Demo เสมอ ไม่มีการเรียก Firebase/AI จริงใน Demo

1. ดูตัวอย่าง 21 บันทึก: ทันเวลา 17 และย้อนหลัง 4
2. ขยาย “ตรวจข้อมูลที่จะใช้สรุป” ติ๊กว่าตรวจแล้ว แล้วกดสร้างสรุปจำลอง
3. ลอง “กรณีไม่มีข้อมูล” ปุ่มสร้างสรุปต้องปิด

ข้อมูลจริงต้องเปิดจากโดเมนและเบราว์เซอร์เดียวกับแอปที่จับคู่เป็นผู้ดูแลไว้ แล้วกด “ข้อมูลผู้ดูแลของฉัน” ยังไม่ได้เพิ่มเมนูเข้า FR-09 ในหน้าเดิมเพื่อรักษาไฟล์ของเพื่อน และยังไม่เผยแพร่หน้าใหม่นี้

## จุดที่เจ้าของควรอธิบายได้

- ไม่มีบันทึกไม่ได้แปลว่าไม่มีการกินยา เพราะระบบเก็บการกดยืนยัน ไม่ได้เก็บประวัติตารางมื้อทุกวัน
- `confirmStatus` เดิมตัดสินทันเวลา/ย้อนหลัง จึงไม่เขียนกฎ T+15 ซ้ำ
- สร้าง object ใหม่ด้วย allowlist แทนส่ง Dose ทั้งก้อน และตรวจรหัสผล AI ซ้ำก่อนแสดง
- เลขรอบคำขอทำให้ผลที่มาช้าหลังเปลี่ยนโหมด/ถอนสิทธิ์ถูกทิ้ง วันเปลี่ยนต้องตรวจข้อมูลใหม่
- เทสต์จำลองยืนยันตรรกะ แต่ยังต้องตรวจ Firebase/App Check/AI และมือถือจริงก่อนรับงาน
