## วิธีผสม "ต้นแบบเก่า" กับ "การออกแบบใหม่" (คำถามของ PM 2 พ.ย. — ตอบ: ทำได้ และเจ้าของหน้าเป็นผู้ทำ)
**หลักคิด:** เก็บสิ่งที่ใช้ได้ (โครงหน้า, ข้อความ ไทย/อังกฤษ, ป้าย FR/BR ต่อหน้า, สถานะว่าง/ผิดพลาด) แล้ว **เปลี่ยนหน้าตาผ่าน token ที่เดียว** จากนั้นค่อยออกแบบใหม่ทีละหน้าที่เจ้าของต้องการ — ไม่รื้อทั้งไฟล์

### ไฟล์เก่าประกอบด้วยอะไร (ตรวจจากไฟล์ที่แนบมา — ตรวจซ้ำกับไฟล์จริงตอนนำเข้า)
| ส่วน | อยู่ที่ไหน | ผลต่อวิธีแก้ |
|---|---|---|
| **ข้อความและสถานะทุกหน้า** (ไทย/อังกฤษ, `covers`, `states` 48 รายการ) | ข้อมูล JSON ก้อนเดียวต้นไฟล์ (`window.MMCopy`) แต่ละหน้ามี `key`, `covers`, `th`, `en` | แก้ข้อความ/ป้าย FR ได้ **ที่เดียว** ไม่ต้องไล่แก้ HTML |
| **ตัววาดหน้าจอ** | สคริปต์ "editable capture views" + สคริปต์นำทาง (`?screen=<key>`) | เพิ่ม/แก้หน้าได้ทีละ key |
| **สไตล์** | `:root` มี token 26 ตัว แต่ **ยังมีสี hex อีกราว 30 ค่านอก `:root`** | ต้องแปลงเป็น token ก่อน (ข้อ 1 ด้านล่าง) |
| ไลบรารีสร้าง QR + ไอคอน + ฟอนต์ฝัง | ฝังในไฟล์ | ไฟล์ใหญ่ (หลายร้อย KB) → conflict ง่ายถ้าหลายคนแก้พร้อมกัน |

### ข้อควรระวังเมื่อเอาของเก่ามาใช้
1. **เจ้าของไฟล์เก่าต้องอธิบายได้ทุกหน้า** (สอบปากเปล่า) และบันทึกการใช้ AI ตามจริงใน `docs/AI_USAGE_LOG.md` (ถ้าไฟล์เก่าสร้างด้วย AI ให้ลงด้วย)
2. **เลข FR/BR ในไฟล์เก่ามาจาก SRS ก่อนหน้า** — ต้องเทียบกับ SRS v1.4 ทุกหน้า ห้ามสันนิษฐาน
3. **ข้อความตัวอย่างต้องเป็นข้อมูลสมมติเท่านั้น** ห้ามมีชื่อ HN โรงพยาบาล หรือฉลากจริง (ไฟล์เก่ามีกติกานี้ในหมายเหตุอยู่แล้ว ให้คงไว้)
4. ถ้าหน้าใดทำใหม่ทั้งหน้า ให้เก็บหน้าเดิมเป็น `NOTES.md` หัวข้อ "แทนที่แล้ว" ว่าเปลี่ยนเพราะอะไร (ใช้ตอบ "ทำไม" ตอนนำเสนอ)
