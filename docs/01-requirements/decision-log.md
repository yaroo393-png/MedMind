## 3. ประเด็นที่ยังสรุปไม่ได้
- **Security Rules ที่แก้ใหม่ยังไม่เคยรันใน Emulator** (นิพจน์เปรียบเทียบเวลา, `request.time`, `duration.value`, เงื่อนไข ternary) — เขียนจากเอกสารกฎของ Firestore ตามความเข้าใจ ยังไม่ยืนยัน
- **พฤติกรรม `serverTimestamp()` ของการเขียนที่ถูกพักตอนออฟไลน์** ในโปรเจกต์นี้ยังไม่ได้ทดสอบจริงบน Android/iPhone (ต้องใช้ MT-05 และ Emulator)
- **ยังไม่ได้รับฉลากตัวอย่าง** (A2 ตอบว่าส่งได้ แต่ยังไม่มีข้อมูล) จึงยังสรุปไม่ได้ว่ารูปแบบ slot ครอบคลุมฉลากส่วนใหญ่หรือไม่ (เช่น "ก่อนอาหาร 30 นาที เช้า-เย็น")
- **iOS (DL-06):** ยังไม่ทราบรุ่น iPhone/เวอร์ชัน iOS และยังไม่เคยทดสอบ — ความเสี่ยงที่ต้องตรวจจริง (ดู architecture §11): Safari อาจพักหน้าเว็บเมื่อล็อกจอ, การเก็บข้อมูลในเครื่อง/สถานะล็อกอินแบบไม่ระบุตัวตนอาจถูกล้างเมื่อไม่ได้ใช้นาน (ตามที่ผมทราบ ยังไม่ได้ยืนยัน), เสียงเล่นหลังแตะครั้งแรก
- **เอกสารรีวิวของทีมไม่มีลายเซ็นรายคนและวันที่อนุมัติ** — ผู้รับรองบันทึกตามที่ PM แจ้ง (สมาชิกทั้ง 5 คน) ถ้าอาจารย์ขอหลักฐาน ให้ใช้ประวัติ PR/ความเห็นของสมาชิกใน GitHub
- **จำนวนคะแนน/การเตรียมสอบปากเปล่า** ไม่เกี่ยวกับมติรอบนี้ แต่สมาชิกที่ถือ FR-02–05 ต้องอธิบาย slot, `confirmStatus` และ `alertFor` ได้ก่อนเขียนโค้ด
