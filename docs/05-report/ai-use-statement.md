## 2. ใช้ AI ตรงไหนบ้าง
สรุปจาก log (ดูรายละเอียดทีละครั้งในไฟล์ log):
1. ร่าง user story, AC, NFR, business rule และ use case ของ SRS — ตัดขอบเขตเหลือ 5 FR ที่ตรงกับปัญหาจริง และให้ทีมตัดสินกฎการเตือน/ข้อความ/ตัวเลขเอง
2. ตรวจ SRS เทียบคู่มือ M2 และตัวอย่างอาจารย์ (stakeholder, MoSCoW, PDPA)
3. เปลี่ยนเป็นฟีเจอร์อ่านฉลากด้วย AI + ออกแบบการปิดชื่อ/HN ก่อนส่ง + เพิ่ม FR-09 (Could)
4. ตรวจคำแนะนำเทคโนโลยีจาก Google ซึ่งผิดเรื่องภาษาไทยของ ML Kit
5. ร่างเอกสารออกแบบและโครง repo (ทีมตรวจและตัดสินใจ)
6. [ ] เพิ่มตามจริงเมื่อใช้ AI เขียนโค้ด/เทสต์

## 4. อะไรได้ผล / ไม่ได้ผล
- ได้ผล: ร่างโครงเอกสารและตารางเร็ว, ชี้ช่องโหว่ของ SRS (เช่น เปิดหน้ากลับหลังปิด, เสียงเล่นหลังแตะครั้งแรก), เปรียบเทียบทางเลือกพร้อมข้อเสีย
- ไม่ได้ผล / ต้องแก้: AI เคยเพิ่ม FR ที่ไม่มีในปัญหาจริงและหยิบเนื้อหาจากงานเก่า · ตอบว่า ML Kit อ่านไทยได้ (ผิด) · เคยตีความเกณฑ์ "AI หรือตรรกะ" เกินจริง — ต้องตรวจกับเอกสารทางการ/เอกสารอาจารย์เสมอ
- [ ] เพิ่ม: ปัญหาที่พบตอนใช้ AI เขียนโค้ด

## 5. มาตรการความปลอดภัยเมื่อใช้ AI
- ไม่ส่งชื่อ/HN/ข้อมูลผู้ป่วยจริงให้ AI ทั้งตอนพัฒนาและในระบบ (BR-19) · ไม่ใส่ secret ใน prompt/โค้ด (CI ตรวจ)
- AI ในระบบแค่ร่าง ผู้ดูแลตรวจทุกครั้ง ไม่ให้คำแนะนำทางการแพทย์ · เวลาเตือนคำนวณด้วยกฎของระบบ
- ตรวจเงื่อนไขการใช้ข้อมูลของบริการ AI ฟรี (อาจนำข้อมูลไปปรับปรุงผลิตภัณฑ์) และแจ้งในหน้ายินยอม
